# Flat source reader and bounded imports

Sources use a persistent file list on the left and an inline reader in the remaining page width. Selecting a file updates the `source` query parameter; refreshes and Artifact links reopen that source. Narrow screens stack the list above the reader. The app shell and Learn page have no fixed maximum width. Reading and saved highlights use flat document/row layouts, while source creation remains a modal.

The modal first asks for Website, File or Text and shows only the relevant inputs. Website/File processing disables the form and prevents closing by Escape, backdrop or close button until the operation completes. Cancel processing stops the request and discards any queued PDF import. Extraction results are editable before Add source; no workspace is changed until the user adds the source. Changing the input URL/file invalidates the previous extraction. Failures retain the input and offer pasted text.

Website extraction is owned by Learn at `POST /api/v1/learn/sources/website`. It requires owner authorization and CSRF. Only public HTTP(S) addresses on ports 80/443 are accepted; DNS answers are checked and the socket connects to the checked address, preserving the original hostname for TLS certificate verification. Each redirect is revalidated. Cookies, credentials, environment proxies and scripts are not used. Requests have bounded concurrency, DNS/socket/deadline limits, at most three redirects and a 2 MB response limit. HTML is reduced to article/main/body text with paragraph/list boundaries; scripts, style, navigation, hidden nodes and comments are removed. JavaScript-only, blocked, compressed-only and otherwise unreadable sites fall back to pasting. This does not bypass access controls or launch a browser engine.

Text and Markdown files are decoded locally as UTF-8. HTML uses authenticated `POST /api/v1/learn/sources/file`; the endpoint also supports UTF-8 text/Markdown. Files are limited to 5,000,000 bytes (5 MB), independently of the website download limit. Non-PDF parsing remains synchronous with a 12-second deadline.

PDF uploads return HTTP 202 with an import ID. Learn registers `learn.sourceImport.v1` with the existing worker; the browser polls `GET /api/v1/learn/sources/imports/{id}` for queued, processing, ready or failed status. The upload requires an Idempotency-Key, owner authorization and CSRF; status and DELETE are owner-scoped. PDF bytes and results are temporary rows in the Learn schema, separate from the saved workspace. Bytes are removed after processing, cancellation removes the row, and worker maintenance removes abandoned rows after one hour. At most five retained imports per owner are admitted. Job payloads and idempotency receipts do not contain document text or file bytes. Saving the reviewed result remains a separate workspace operation.

PDFs must be unencrypted and contain at most 100 pages. The parser first extracts existing text with pypdf. If a page has no readable text, OCRmyPDF/Tesseract adds an English OCR text layer, skipping pages that already have text. The output page count must match the input; original selectable text is preserved, and recognized text fills the other pages in order. This does not recognize additional image text on pages that already contain selectable text. English is bundled in Docker; other OCR languages are not yet exposed in the import dialog. OCR output is editable before saving and should be reviewed for recognition errors.

PDF processing runs in an isolated process group with a five-minute wall deadline, one OCR worker, a 1.5 GiB per-process address-space limit and a 256 MiB per-file scratch limit. Docker worker scratch storage is capped at 1 GiB. Timeout and cancellation terminate descendants and remove scratch files. The job lease allows another minute for finishing; the worker publishes heartbeats during long jobs. Failed imports show a specific message where possible and support processing again or pasting text.

The existing 200,000-character per-source and 800 KB per-workspace limits still apply. Full original-file retention, page-level PDF locators and Knowledge resource-level persistence remain separate follow-ups. The older Library screen continues to use its mock adapter. No external AI service is involved in import or OCR.
